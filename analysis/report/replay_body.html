The problem

Put videos in caches so requests travel less

Every video lives in the data center. Cache servers sit closer to the users but hold only X MB each. You choose which videos to copy into which caches; each request is then served from the fastest place that has its video.

Videos

V videos, each with a size in MB. The data center holds all of them.

Caches

C cache servers, all with the same capacity X MB. They start empty.

Endpoints

Groups of users. Each has a latency to the data center and to some of the caches, never slower than the data center.

Requests

“Endpoint e asks for video v, n times.” Served by the fastest connected cache holding v, otherwise by the data center.

score = ⌊ 1000 × Σrequests n × (latencydata center − latencyserved) ÷ Σrequests n ⌋   = average milliseconds saved per request, × 1000

    Where the data comes from. The greedy traces come from a lazy re-implementation of greedy_density using the same density rule and the same tie-breaking (lowest video id, then lowest cache id). On all six instances its final placements match the team's output exactly. The knapsack phase starts from that solution and rewrites each cache optimally with the others fixed, sweep after sweep, until no cache improves. The me_at_the_zoo optimum is the HiGHS MIP solution from the atlas.
